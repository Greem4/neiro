## Планы

### Карточки детей

Крупная фича, взята на потом. Данные считаются из того, что уже есть:
`effectiveDayData` + `SessionParser`, заготовка `computeRecentStudents` в
`CalendarViewModel`, переход из профиля стоит выключенной заглушкой.

- [ ] Экран списка учеников
- [ ] Карточка ребёнка: посещения / пропуски / отмены
- [ ] График посещаемости по месяцам
- [ ] Сумма принесённых денег
- [ ] Краткая история (даты, дни недели)
- [ ] Поиск ученика по имени — делается вместе с карточками, отдельно смысла нет

### Групповые занятия по `activity_id`

Нейройога, подгрупповые, «Мы вместе» сейчас не ловятся: групповым считается то,
где в названии есть слово «интенсив». Правильный признак — `activity_id` у
записи, он уже приходит в `RecordData`. Решено делать, но не срочно.

### Тесты обновления

Крайние случаи проверяются кодом, а не руками на телефоне — гоняются в CI на
каждый push.

- [ ] Подменённая сумма — `UpdateVerifier` возвращает отказ, файл удалён
- [ ] Обрыв сети посреди закачки — `UpdateDownloader` даёт внятную ошибку,
      огрызок файла стёрт
- [ ] Чужая подпись — проверяется один раз руками на телефоне: читается через
      `PackageManager`, а тащить ради этого Robolectric не стоит
- [ ] Установка из RuStore (`adb install -i ru.vk.store`) — когда-нибудь потом

### Сплошное покрытие тестами

Правки статусов 01.09.2026 показали дыру: «пришёл» и «оплачено» разъехались,
а поймали это три упавших теста из трёхсот шестидесяти — остальные места,
где считаются деньги и «проведено», проверять нечем. Нужен разбор по
модулям: где поведение важное, там тест, а не надежда на ручную проверку
на телефоне.

- [ ] Разбор статусов и денег: `SessionParser`, `MonthRatesResolver`,
      `CalendarStatsCalculator`, `DaySummaryStats`, `IntensiveSessionUtils` —
      каждый статус (`0/1/2/3/4`) в каждом счётчике, включая старый формат
      `name|true` и интенсив с детьми и без
- [ ] Синхронизация с YClients: слияние с локальным днём, догон по
      `changed_after`, применение пуш-событий, расхождение с архивом
- [ ] Разбор и сериализация записей туда-обратно на всех форматах,
      включая поля с `|` внутри
- [ ] Список того, что осталось непокрытым, — в `docs/debt.md`, чтобы дыра
      была видна, а не забыта

### Интерфейс дня — известные проблемы

Замечено 01.09.2026 на боевом телефоне после выхода 0.2.5. Все четыре — про
экран дня и диалог расхождений с архивом.

- [ ] **Архив завален расхождением «Пришёл ↔ Оплачено».** Архив импортирован
      до 0.2.5, отдельного «оплачено» в нём нет: YClients теперь отдаёт
      `Оплачено`, архив помнит `Пришёл`, и `ArchiveSyncCompare.differs`
      (`app/src/main/java/ru/greemlab/neiro/ui/calendar/ArchiveSyncCompare.kt`)
      метит почти каждый архивный день как несовпадающий. Диалог «Обновить
      архив?» в таком виде затрёт все ручные правки. Развилка, нужен выбор
      владельца:
      1. Разовая миграция при загрузке архива: где в архиве `Пришёл`, а
         близнец в YClients `Оплачено` и остальные поля совпадают — поднять
         статус в архиве до `Оплачено`. Единый источник, но необратимо —
         нужен снимок архива и откат.
      2. Не считать `Пришёл` и `Оплачено` расхождением для дней, записанных
         до 0.2.5 (нужна метка версии на архивном дне). Дешевле, но два
         представления одного факта живут рядом.
      3. Сравнивать только «проведён / не проведён», оплату из архивного
         diff убрать вовсе. Дёшево, но настоящее расхождение по оплате в
         архиве больше не увидеть.
      Пересекается с бэклогом «Мастер слияния при конфликте архив ↔ YClients».
- [ ] **Плашки с двумя людьми не нажимаются.** Замена и «интенсив накрыл
      занятие» (`ExpandableReplacementSlot`, `ExpandableIntensiveCoverSlot` в
      `app/src/main/java/ru/greemlab/neiro/ui/components/daydetails/ScheduleSlotItem.kt`)
      получают только `onContentClick`, а `onStudentStatusChange` из
      `DayScheduleTimeline` в них не проброшен вовсе — быстрый тап «пришёл /
      оплатил» по «!» для таких слотов мёртв даже в архиве. Плюс
      горизонтальный `pointerInput` на всей плашке и `indication = null` —
      нажатие без отклика, ощущается как неинтерактивное. Пробросить статус в
      свёрнутую карточку и в раскрытые дочерние, дать отклик на тап.
- [ ] **Предупреждение о расхождении просвечивает первой записью.** Шапка
      диалога дня (`DayDetailsContent` в
      `app/src/main/java/ru/greemlab/neiro/ui/components/DayDetailsDialog.kt`)
      залита только `panelScrim` (плотно сверху, прозрачно снизу), а лента
      `DayScheduleTimeline` край не гасит — `fadingEdges` на её прокрутку не
      наложен. Слот, уехавший под шапку, виден сквозь баннер и иконку «!».
      Наложить `fadingEdges(top = headerHeight, bottom = footerHeight)` на
      прокрутку ленты — как уже сделано в диалогах статистики дня.
- [ ] **Кривые края и нет полосы прокрутки в «Отличия архива от YClients».**
      `ArchiveMismatchDetailsDialog` (тот же `DayDetailsDialog.kt`) гасит верх
      и низ безусловно (`fadingEdges(top, bottom)`), поэтому первая и
      последняя строки полупрозрачны даже когда список докручен до упора —
      читается как обрезанный текст. Взять `fadingScrollEdges(scrollState)`
      (уже есть в `app/src/main/java/ru/greemlab/neiro/ui/util/fadingEdges.kt`)
      и добавить тонкую полосу прокрутки, чтобы было видно, что список длинный
      и насколько прокручен.

## Не планируется сейчас

- **PDF / отчёт за месяц** — не нужен, вычеркнут 13.08.2026
- **Compose UI-тесты** (календарь, drawer, диалог дня) — вычеркнуты
  13.08.2026: нужен эмулятор, идут минутами и ломаются от любой правки
  вёрстки. Логика проверяется обычными тестами, их 44
- **Проверка обновления на Android ниже 12** — не проверяем, версия неактуальна
- **Ротация `partner_token` YClients.** Ключ лежал в публичных APK версий до
  `0.1.0` и секретом не является. Решено 13.08.2026 не менять: в кабинете
  YClients перевыпуск не нашёлся, а риск владелец принимает осознанно —
  разбор остаётся в [`docs/updater/RISKS.md`](docs/updater/RISKS.md#секреты-в-публичном-apk)
- **Любая запись в YClients** — смена статуса, перенос, правка записи через
  API. У аккаунта нет прав на запись, и они не нужны: приложение только
  читает, ручные правки живут в архиве и наружу не уезжают
- **Периодическая синхронизация «каждые 4 часа»** — заменена на live-опрос
  (1 мин днём / 60 мин ночью МСК) и дневную автосинхронизацию при открытии
