# План работ

Этап = законченная порция = один коммит. Сначала сервер целиком (его можно
проверить `curl`-ом, не трогая приложение), потом клиент, потом запуск по
[ROLLOUT.md](ROLLOUT.md).

Ничего из работающего по дороге не выключается: `neiro-push-events` и
установленное приложение живут своей жизнью до самого конца.

Легенда: `[ ]` не начато, `[~]` в работе, `[x]` готово.

---

## Часть 1. Сервер

### Этап 1 — каркас сервиса

- [ ] Каталог `neiro-push/` — перенос из `neiro-push-events`: `config.py`,
      `database.py`, `security.py`, `events.py`, `fcm.py`, `poller.py`,
      `dashboard.py`, `templates/`, `Dockerfile`, `requirements.txt`, тесты
- [ ] Схема БД сразу в целевом виде ([ARCHITECTURE.md](ARCHITECTURE.md#схема-бд)):
      без `partner_token_enc`, с `token_hash`, `revoked_at`, `reauth_required`,
      `user_login`, `last_auth_at`
- [ ] `config.py`: `YCLIENTS_PARTNER_TOKEN`, `YCLIENTS_COMPANY_ID`, порт 8012,
      `DATABASE_PATH=/data/neiro_push.db`
- [ ] `docker-compose.yml`: контейнер `neiro-push`, порт `127.0.0.1:8012:8012`,
      том `neiro_push_data`
- [ ] Поллер берёт `partner_token` из настроек и пропускает аккаунты с
      `reauth_required`

**Готово, когда:** `./neiro-push/scripts/dev.sh` поднимает сервис локально,
тесты, перенесённые из старого сервиса, зелёные.

**Коммит:** `Завёл сервис neiro-push на базе push-events`

### Этап 2 — вход и device_token

- [ ] `app/auth.py`: `POST /v1/auth/login`, `POST /v1/auth/logout`,
      `GET /v1/session`, `POST /v1/devices/fcm`
- [ ] `yclients.py`: `login` (partner-токеном), `fetch_staff` и определение
      `staff_id` по имени — логика переезжает из
      `YClientsRepository.detectAndSaveStaffId`
- [ ] Выпуск `device_token`: 32 случайных байта, в БД только `sha256`
- [ ] Зависимость `require_device`: токен → устройство → аккаунт, проверка
      `revoked_at` и `reauth_required`
- [ ] Пароль не попадает ни в логи, ни в трейсбеки — с тестом на это
- [ ] Тесты: успешный вход, неверный пароль (`401`), имя не совпало (`409`),
      повторный вход с того же `device_id` (старый токен мёртв, курсор цел)

**Готово, когда:** цикл «вход → `/v1/session` → выход» проходит `curl`-ом, в
БД лежит аккаунт с зашифрованным `user_token` и устройство с хэшем токена.

**Коммит:** `Добавил вход и device_token в neiro-push`

### Этап 3 — прокси YClients

- [ ] `app/proxy.py`: семь эндпоинтов из
      [API.md § Прокси](API.md#прокси-yclients)
- [ ] `company_id` и `staff_id` подставляются из аккаунта, из запроса не
      принимаются вовсе
- [ ] Тело и код ответа YClients пробрасываются без изменений
- [ ] Единый обработчик: `401` от YClients → `reauth_required` + `409`,
      5xx → `502`, таймаут → `504`
- [ ] Три подряд `401`, а не первый же, взводят `reauth_required`
      ([RISKS.md](RISKS.md#протухший-user_token))
- [ ] Тесты на подменённом YClients: проброс тела, подстановка `staff_id`,
      каждая ветка ошибок

**Готово, когда:** ответ `/v1/yclients/records` побайтово совпадает с ответом
YClients на тот же период, полученным напрямую.

**Коммит:** `Добавил прокси YClients в neiro-push`

### Этап 4 — лимиты и отзыв доступа

- [ ] `app/ratelimit.py`: 5 попыток входа / 15 мин на `device_id` и на IP,
      60 запросов / мин на устройство, `Retry-After` в ответе
- [ ] Пятая неудачная попытка входа пишется в лог — единственный способ
      заметить перебор
- [ ] Дашборд: кнопки «отозвать устройство» и «сбросить аккаунт»
- [ ] `scripts/revoke-device.sh`

**Коммит:** `Добавил лимиты и отзыв устройств`

### Этап 5 — деплой рядом с работающим

- [ ] Скрипты по [DEPLOY.md § Скрипты](DEPLOY.md#скрипты): `deploy.sh`,
      `install-tunnel.sh` (порт 18083), `patch-vps-nginx-v1.sh`
      (`proxy_pass` **без** завершающего слеша), `dev.sh`, `logs.sh`,
      `backup.sh`, `restore.sh`
- [ ] `deploy.sh` падает с внятным сообщением при пустом
      `YCLIENTS_PARTNER_TOKEN`
- [ ] Уборка первого поколения на Pi — по чек-листу
      [ROLLOUT.md § Шаг 0](ROLLOUT.md#шаг-0--подготовка-ничего-не-запускается)
- [ ] Развёртывание: оба контейнера живы, `docker ps` показывает 8011 и 8012

**Готово, когда:** пройдены шаги 1 и 2 из [ROLLOUT.md](ROLLOUT.md), публичный
`/v1/health` отвечает, старый сервис работает как ни в чём не бывало.

**Коммит:** `Добавил деплой neiro-push на маршрут /v1`

## Порядок относительно других работ

Самообновление ([docs/updater/](../updater/README.md)) и этот проект
пересекаются в одной точке: **первый публичный APK не должен содержать
`partner_token`**.

Рекомендуемый порядок — сервер (этапы 1–5) и приложение (6–8) до релиза
`v0.1.0`, тогда первая же публичная сборка выходит чистой и вопрос закрыт
навсегда. Если релиз захочется выпустить раньше — собрать его с пустым
`YCLIENTS_PARTNER_TOKEN` и вводить токен вручную (форма для этого пока ещё
есть), а прокси приедет следующей версией.

Чего делать нельзя ни при каком порядке: выложить публично APK с зашитым
`partner_token`. Скачанный файл не отзывается.
