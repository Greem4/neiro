# План работ

Этап = законченная порция = один коммит. Сначала сервер целиком (его можно
проверить `curl`-ом, не трогая приложение), потом клиент, потом запуск по
[ROLLOUT.md](ROLLOUT.md).

Ничего из работающего по дороге не выключается: `neiro-push-events` и
установленное приложение живут своей жизнью до самого конца.

Легенда: `[ ]` не начато, `[~]` в работе, `[x]` готово.

## Часть 2. Приложение

### Этапы 6 и 7 — сетевой слой на прокси, вход одним действием

Сделаны одним коммитом: разделить их нечем. Оба меняют один контракт, и
промежуточное состояние — репозиторий уже без `partner_token`, а
`PushRegistrar` ещё регистрирует устройство им же — просто не собирается.

- [x] `YClientsClient`: базовый URL сервиса, заголовок
      `Authorization: Bearer <device_token>`; ключ приложения подставляется
      только на `/v1/auth/login`
- [x] `YClientsApi`: пути прокси, из сигнатур уходят `companyId` и `staffId`
- [x] `NeiroApi` (новый): `login`, `logout`, `session`, `devices/fcm`
- [x] `TokenStorage`: `deviceToken` вместо `partnerToken`/`userToken`/`companyId`;
      токены прошлых версий стираются при старте
- [x] `YClientsRepository`: `login` через сервис, обработка `401` (полный
      выход) и `409` (повторный вход паролем), `detectAndSaveStaffId` удалён
- [x] `BuildConfig`: `YCLIENTS_PARTNER_TOKEN` и `YCLIENTS_COMPANY_ID` удалены
      из `app/build.gradle.kts` и из релизного workflow
- [x] `PushRegistrar`: регистрация слита со входом; остаётся обновление
      `fcm_token`, сверка сессии и отзыв устройства при выходе
- [x] `PushApi`: только лента событий, `device_id` из путей ушёл;
      `PushClient` удалён — Retrofit на сервис теперь один
- [x] Отложенный отзыв: не прошёл при выходе — токен хранится и отзывается
      при следующем старте, иначе устройство осталось бы получать чужие пуши
- [x] Форма `PartnerTokenSetup` удалена из `AuthScreen` и `AuthViewModel`
- [x] Экран входа: тексты под коды сервиса, состояние «нужен повторный вход»
      для `reauth_required`, логин подставляется из прошлого входа

## Порядок относительно других работ

Самообновление ([docs/updater/](../updater/README.md)) и этот проект
пересекаются в одной точке: **первый публичный APK не должен содержать
`partner_token`**.

Рекомендуемый порядок — сервер (этапы 1–5) и приложение (6–8) до релиза
`v0.1.0`, тогда первая же публичная сборка выходит чистой и вопрос закрыт
навсегда. Если релиз захочется выпустить раньше — собрать его с пустым
`YCLIENTS_PARTNER_TOKEN` и вводить токен вручную (форма для этого пока ещё
есть), а прокси приедет следующей версией.

Чего делать нельзя ни при каком порядке: выложить публично APK с зашитым
`partner_token`. Скачанный файл не отзывается.
