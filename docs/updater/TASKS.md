# План работ

Этап = законченная порция = один коммит. Порядок важен: каждый следующий этап
опирается на предыдущий и проверяется отдельно. Не сваливать несколько этапов
в один коммит — в таком коммите незамеченной проезжает поломка, и его
невозможно откатить по частям.

Сборку и проверку на устройстве делает владелец проекта: агент Gradle не
запускает. Поэтому у каждого этапа критерий готовности написан так, чтобы его
можно было проверить глазами по коду или одной командой.

Легенда: `[ ]` не начато, `[~]` в работе, `[x]` готово.

## Как работать по этому плану

Читать первым делом — здесь всё, что нужно знать агенту, севшему за работу.
Отдельных указаний в задаче не будет: «работай по плану» означает то, что
написано ниже.

1. **С чего начать** — со строки «Ближайшее действие» в таблице
   [«Где мы сейчас»](#где-мы-сейчас). Дальше по порядку блоков.
2. **Один этап — один локальный коммит**, сообщение берётся из самого этапа.
   Несколько этапов в один коммит не сваливать.
3. **Не пушить и не создавать PR.** Пуш, PR и слияние в `main` делает
   владелец. Работать в текущей ветке.
4. **Gradle не запускать** — ни `assembleDebug`, ни тесты. Сборку и проверку
   на устройстве делает владелец. Код писать так, чтобы собрался с первого
   раза, но проверять сборкой не пытаться.
5. **Статусы отмечать честно.** После этапа обновить таблицу «Где мы сейчас»:
   `[x]` — только тому, что действительно проверено; коду, который ещё не
   собирали, — `[~]` с припиской, что осталось проверить.
6. **Не трогать чужое.** Push-контур (`push/`, `neiro-push/`), синхронизацию
   YClients, расчёт денег и `SessionNotificationCoordinator` этот план не
   меняет. Полный список файлов, которые вообще можно править, —
   [ARCHITECTURE.md § Точки встраивания](ARCHITECTURE.md#точки-встраивания).
7. **Расходится план с кодом — остановиться и спросить**, не подгонять молча.

Что делает владелец, а не агент: секреты в GitHub, слияние в `main`, тег,
этап [О7](#этап-о7--карточка-репозитория-на-github) (настройки репозитория),
[10](#этап-10--скриншоты) (скриншоты) и [11](#этап-11--проверка-на-устройстве)
(проверка на устройстве). Этап [О8](#этап-о8--заметки-релиза-из-changelog) —
только после первого успешного релиза.

## Порядок работ

Четыре блока. Внутри блока порядок жёсткий, блоки Б и В частично
перекрываются: код этапов 3–5 можно писать до тега, проверить — только после.

```
А. Публичное лицо репозитория     О1 → О2 → О3 → О4 → О5 → О6 → О7
   (файлы и настройки, кода не касаются)
                    │
Б. Первый релиз     секреты (владелец) → слияние в main → v0.1.0
                    │
В. Самообновление   3 → 4 → 5 → 6 → 7 → 8 → 9 → О8
   в приложении     (пакет ru.greemlab.neiro.update)
                    │
Г. Доводка          10 (скриншоты) → 11 (проверка на устройстве)
```

Почему оформление идёт **до** тега: релиз — первое, что видит посторонний
человек. Репозиторий без лицензии формально запрещает использовать код, а
описания «что это и как помочь» у GitHub спрашивают ровно в тот момент, когда
кто-то пришёл по ссылке на релиз. Один раз сделать до, а не догонять после.

Почему тег блокирует блок В: приложению нужен настоящий релиз, чтобы было что
находить. Этапы 4–9 без него проверить нечем — можно написать, но нельзя
закрыть.

# Блок А. Публичное лицо репозитория

Репозиторий публичный с самого начала, но выглядит как рабочий стол: ни
описания, ни лицензии, ни объяснения, что делать пришедшему. Семь коротких
этапов, каждый — один файл и один коммит. Кода приложения ни один из них не
касается, поэтому их можно делать в любой свободный момент и не бояться, что
что-то отвалится.

## Этап О1 — лицензия MIT

Решено 11.08.2026: **MIT**. Причина — личный инструмент с открытым кодом,
запрещать нечего, а текст лицензии короткий и понятный без юриста.

- [x] `LICENSE` в корне: канонический текст MIT, строка

- [x] Бейдж в README рядом с существующими:
      `[![Лицензия MIT](https://img.shields.io/github/license/Greem4/neiro?label=лицензия&color=blue)](LICENSE)`
- [x] Раздел «Лицензия» в конце README: одна фраза и ссылка на файл
- [ ] Строка про лицензию в [`CONTRIBUTING.md`](#этап-о2--contributing), когда

Текст не сочинять и не переводить: GitHub определяет лицензию сравнением с
эталоном, изменённый текст он не распознает и покажет «Other».

**Готово, когда:** `gh repo view --json licenseInfo` возвращает `MIT License`
вместо `null`, а в шапке репозитория на GitHub появилась плашка `MIT`.
