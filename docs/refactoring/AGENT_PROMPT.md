## ТЕКСТ ПРОМПТА (копировать целиком, начиная со следующей строки)

Я заранее подготовил подробный план рефакторинга в папке `docs/refactoring/`. Твоя задача — последовательно выполнить этапы 1–6 по этим документам.

**Правила работы:**

1. **Читай и следуй документам в порядке их перечисления в `docs/refactoring/README.md`.** Рекомендуемая последовательность: `1 → 5 → 2 → 3 → 4 → 6` (Этап 1 первым, Этап 6 последним).
2. **Не отступай от документов.** Если правка в коде расходится с описанием (другой номер строки, изменившийся код) — ищи блок по контексту (3–5 строк до и после), не пытайся править на глаз.
3. **Не правь файлы вне списка `Файлы для правки` соответствующего этапа** без необходимости. Если необходимо — обоснуй в комментарии под именем коммита.
4. **Не запускай Gradle.** Сборку и проверку выполняет пользователь. Используй `ReadLints` для проверки правок в IDE.
5. **Не трогай**:
   - Архив (`saveDayToArchive`, `deleteDayFromArchive`, `writeSyncCache` без `savedDayJson`).
   - `LaunchedEffect(initialNames, isPlanningMode)` в `DayDetailsDialog`.
   - `isInCurrentMonth` authoritative wipe в `YClientsCalendarSync`.
   - Что-либо из `docs/refactoring/OUT_OF_SCOPE.md`.
6. **Коммиты:**
   - На русском, одна короткая строка ≤ 72 символов, прошедшее время, без `feat:`/`fix:`/`chore:`.
   - В конце каждого этапа в документе уже даны заготовки коммит-сообщений в правильном формате. Бери их как есть.
   - Каждая мелкая правка — отдельный коммит. Не сливай 5 правок в 1 коммит.
   - Не запускай `git push` без явной просьбы.

**Алгоритм работы по каждому этапу:**

1. Прочитай весь markdown этапа целиком.
2. Прочитай **актуальный** код каждого упомянутого файла (`Read`).
3. Сделай первую правку, проверь `ReadLints`. Если линт чистый — `git add` + commit с сообщением из конца документа.
4. Повтори для каждой следующей правки этапа.
5. В конце этапа выполни блок «Финальная проверка этапа» (`rg` команды для верификации).
6. Если что-то не сходится с документом — **не угадывай**, спрашивай у пользователя.

**Старт:**

Начни с **Этапа 1** (`docs/refactoring/ETAP_1_security_configs.md`). После завершения покажи мне список коммитов и переходи к следующему этапу из рекомендуемой последовательности.

Документация рассчитана на ~70 коммитов всего (по всем 6 этапам). Это не должно быть сделано в одном проходе — после каждого этапа я проверю результат вручную.

## КОНЕЦ ПРОМПТА

---

## Параметры для запуска (best practice)

- Дай агенту полный read+write доступ к репозиторию.
- В начале каждой новой сессии — попроси прочитать `docs/refactoring/README.md` и текущий этап из списка todo.
- После каждого этапа: `git log --oneline -20` для контроля коммитов.
- Если агент уйдёт в рабство `OUT_OF_SCOPE` (начнёт делать большие рефакторинги) — прерви, верни на план.

## Проверки после каждого этапа

1. **Этап 1:** open `local.properties` без `RELEASE_STORE_FILE` → попробовать собрать release из IDE → должна быть Gradle ошибка с понятным сообщением. (Опционально пользователю.)
2. **Этап 2:** проверить logout — должен полностью очистить prefs, отменить все WorkManager-задачи (`adb shell dumpsys jobscheduler | grep neiro` или WorkManager Inspector).
3. **Этап 3:** включить уведомления → закрыть и открыть приложение → удалить запись в YClients → проверить, что push приходит один раз, не два.
4. **Этап 4:** открыть YClients WebView → выйти назад → повторить 10 раз → проверить, что память не растёт (Android Profiler).
5. **Этап 5:** войти с истёкшим user_token (либо сменить partner_token на инвалидный) → должно показать «Сессия истекла», login flow открыться.
6. **Этап 6:** push notification → повернуть устройство во время открытия экрана → проверить, что deep-link не сбросился.
