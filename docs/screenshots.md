# Скриншоты приложения

Снимки нужны двум разным адресатам, и требования у них расходятся настолько,
что один набор картинок обоим не годится.

| | README на GitHub | Карточка RuStore |
|---|---|---|
| Что показывает | приложение как есть, живьём | витрину магазина |
| Строка статуса и жесты | **можно** | **запрещены** |
| Пропорции | любые | строго 9:16 или 16:9 |
| Размер | 480 px по ширине хватает | 1080×1920 рекомендованный |
| Формат | PNG | PNG или JPG, до 3 МБ |
| Сколько | 3–4 в ряд | до 10 |

Снимает владелец: агент эмулятор не запускает. Разложить снятое по обоим
наборам умеет [`scripts/screenshots.sh`](../scripts/screenshots.sh).

## Главное правило: на снимках нет настоящих учеников

Календарь Neiro показывает имена детей. Скриншот с ними уезжает в публичный
репозиторий и в магазин — оттуда его уже не отозвать.

Снимать нужно на тестовых данных:

1. Выйти из аккаунта YClients — приложение перейдёт в локальный режим.
2. Импортировать тестовый архив (Профиль → Архив → Импорт JSON) с
   выдуманными именами.
3. Снять всё нужное, потом войти обратно.

Это касается и уведомлений: на снимке шторки текст пуша содержит имя.

## Что снимать

Восемь кадров, четыре экрана в двух темах. Имена файлов важны — по суффиксу
`-dark` скрипт выбирает цвет подложки:

| Имя файла | Экран | Что должно быть видно |
|---|---|---|
| `calendar-light`, `calendar-dark` | Календарь месяца | заполненный месяц, суммы по дням, выделенный день |
| `day-light`, `day-dark` | День целиком | таймлайн занятий со статусами |
| `profile-light`, `profile-dark` | Профиль | график по месяцам, годовая статистика |
| `about-light`, `about-dark` | О программе | версия и кнопка «Проверить обновления» |

Первым в карточке магазина ставится календарь: это главный экран и единственный,
по которому за секунду понятно, что за приложение.

## Как снять и разложить

```bash
# по кадру за раз, на подключённом телефоне
./scripts/screenshots.sh capture calendar-light
./scripts/screenshots.sh capture calendar-dark
# …

# оба набора разом: docs/images/ и store/rustore/
./scripts/screenshots.sh build

# сверить набор магазина с лимитами
./scripts/screenshots.sh check
```

`capture` кладёт исходники в `docs/images/raw/` — они не попадают ни в README,
ни в магазин, но нужны, чтобы пересобрать наборы, не бегая с телефоном заново.

`adb` берётся из Android SDK (`~/Library/Android/sdk/platform-tools/adb`), в
PATH его нет. Другой путь — `ADB=/путь/к/adb ./scripts/screenshots.sh capture …`.

### Обрезка под RuStore

Магазин запрещает элементы интерфейса Android, поэтому скрипт срезает сверху
строку статуса, снизу — полосу жестов, а результат вписывает в кадр 9:16,
закрашивая поля цветом фона темы (`#F8F9FA` светлая, `#121212` тёмная).

Значения обрезки подобраны под экран 1080×2400. Другой телефон — поправить:

```bash
CROP_TOP=140 CROP_BOTTOM=80 ./scripts/screenshots.sh build
```

Проверяется глазами по одному кадру: часов и батареи сверху быть не должно,
полоски жестов снизу — тоже, а содержимое экрана не должно быть срезано.

## Требования RuStore

Из [требований к приложениям](https://www.rustore.ru/help/developers/publishing-and-verifying-apps/requirement-apps)
и консоли разработчика:

**Скриншоты**
- пропорции строго **9:16** (вертикальные) или **16:9** — прочее магазин
  обрежет сам, и не там, где нужно;
- рекомендованный размер **1080×1920**, допустимо от 320 до 3840 px по стороне;
- PNG или JPG, до **3 МБ** на файл, до **10** штук на тип устройства;
- **не должно быть элементов интерфейса Android** — строки статуса, кнопок
  навигации, шторки;
- только настоящий интерфейс текущей версии: заставки, баннеры и экраны входа
  вместо приложения не принимаются;
- функциональности, которой нет или уже нет, на снимках быть не должно.

**Иконка** — 1:1, от 32×32 до 512×512, до 1 МБ.
В репозитории лежит [`store/icon-512.png`](../store/icon-512.png): 512×512,
17 КБ — подходит как есть.

**Тексты карточки** — название до 80 символов, краткое описание до 80,
полное до 4000.

**Видео** — одно, MP4, 1–2 минуты, необязательно.

Цифры по количеству, весу и диапазону разрешений взяты из ASO-руководств по
RuStore, а не из официального документа: там прописаны только пропорции.
Перед первой публикацией сверить в кабинете — требования магазина меняются
чаще, чем эта страница.

## Требования README

Отдельных требований нет, есть здравый смысл: снимки лежат в `docs/images/`,
вставляются в ряд по три-четыре, ширина в разметке — 240 px.

Заготовка в [README.md](../README.md) уже стоит и ждёт файлов:

```html
<img src="docs/images/calendar-light.png" width="240" alt="Календарь месяца">
```

Полноразмерные снимки в репозиторий не кладутся: 1080×2400 весит под мегабайт
на кадр, а показывается всё равно в 240 px. Скрипт готовит 480 px — вдвое
больше показываемого, чтобы не мылилось на экранах с высокой плотностью.

  магазине нет, ветка `InstalledFromRuStore` не проверена на живом устройстве
  ([updater/TASKS.md](updater/TASKS.md)). Появится сборка — проверить, что
  самообновление молчит и показывает строку про магазин.
- **`setRequestUpdateOwnership(true)`** в
  [`ApkInstaller`](../app/src/main/java/ru/greemlab/neiro/update/ApkInstaller.kt)
  включён, пока RuStore не используется. Публикация в магазине — повод
  вернуться к этому флагу.
