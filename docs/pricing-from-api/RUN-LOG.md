## Расхождения документов, важные для чисел

### Интенсивы: что вычитается из факта перед делением

RUNBOOK §7 (этап 3) называет параметр `manualIntensiveSum` и комментирует:
«интенсивы, заведённые руками, в факте YClients отсутствуют (GAPS 7)».
Тест-таблица там же: «Есть ручной интенсив на 11 200 → вычитается из базы».

Это противоречит контрольным числам того же RUNBOOK (§9) и
[HISTORY-2025-2026.md](HISTORY-2025-2026.md): июнь 2026 —
`174 450 = 115 × 1400 + 2250 + 11 200`, и в YClients ровно 174 450 (Δ = 0).
То есть интенсив **входит** в факт. Плюс `YClientsCalendarSync`
(`resolveIntensiveSyncAmount`) заводит интенсивы из API с `amountFixed = false`.

Сделано: `MonthLocalFacts` делит интенсивы по происхождению —
`factIntensiveSum` (из API, `amountFixed = false`) вычитается из факта,
`manualIntensiveSum` (заведённые руками) не вычитается, а в сводке дня
прибавляется к факту. При этом:

- контрольная цифра июня 2026 сходится в 1400;
- GAPS 7 («ручные суммы всегда локальные и складываются с фактом») выполняется;
- буквальное чтение тест-таблицы §7 дало бы для июня 1497 ₽ вместо 1400.

Если у центра появятся интенсивы, заведённые руками **для слотов, которые есть
и в YClients**, признак `amountFixed` перестанет быть надёжным — там и придётся
вернуться к вопросу.

### Что показывает закрытый месяц

FOUNDATION §4 и §11: месяц замораживается по цене приложения, до разбора
показывается она. FOUNDATION 3.2: есть факт → цена из факта. Сначала было
разрешено через `frozen` (закрытый месяц отдавал сохранённую цену) — **потом

## Смена модели после прогона: факт из API — главный источник

Решение пользователя 01.08.2026, уже после того как все восемь этапов легли
в ветку. Отменяет часть FOUNDATION.

**Что было.** «Ручной ввод — правда, API — наблюдение» (FOUNDATION §2). Цена
прошлого месяца бралась из профиля, факт лежал рядом в `factGross` и работал
только на бейдж расхождения. Итог: все прошлые месяцы считались по сегодняшней
цене профиля — 1400 ₽, включая август–октябрь 2025, где часть занятий реально
прошла по 1250 (HISTORY §1: «правило "ставка X действует с даты Y" историю не
восстанавливает в принципе»).

**Что стало.**

| Что | Откуда деньги |
|---|---|
| Текущий и будущие месяцы | профиль |
| Прошлый месяц, АВТО | начисление YClients целиком: `factGross − налог` |
| Прошлый месяц, РУЧНОЕ | `занятия × ручная цена` (занятия из календаря, а без него — `factSessions`) |
| Прошлый месяц без факта | сохранённая цена месяца, иначе профиль |

Правки: `resolveMonthRates` (заморозка больше не заслоняет факт),
`mergeFact` (АВТО-цена = цена из факта), `computeProfileYearStats` (сумма месяца
= начисление, а не `цена × занятия`).

**Февраль–май 2026 правятся руками.** YClients там четыре месяца считал по 1500
из-за схемы `percent 50` от нового прайса, на руки было 1400 — разница 39 500 ₽
(HISTORY §1). Хардкода дат в коде нет (RUNBOOK §10, HISTORY §322 требует
«признак "поправка применена вручную"»): человек правит цену в статистике,
месяц становится MANUAL, и синк его больше не переписывает.

**Побочные решения, которых в плане не было:**

- **Пустой ответ API больше не факт.** `gross = 0` и `services = 0` не
  затирают уже полученный `factGross`. Раньше это было безобидно (деньги считал
  профиль), теперь обнулило бы месяц в статистике.
- **Ручные интенсивы прибавляются к начислению.** В `factGross` их нет
  (GAPS §7), а раз сумма месяца теперь берётся из факта, `manualIntensiveSum`
  наконец пошёл в дело — до этого поле считалось, но никуда не влияло.
- **Бейдж расхождения остался только для ручной цены.** У АВТО-месяца
  приложение и YClients теперь говорят одно и то же — разбирать нечего. След
  в `note` пишется по-прежнему. Спрашиваем повторно, только если пришло другое
  начисление, а не то, с которым человек согласился.
- **«Считать как в YClients» в разборе расхождения** возвращает месяц в АВТО
  (`acceptMonthFact`), а не фиксирует сегодняшний факт ручной ценой — иначе
  месяц замер бы навсегда.
- **Заморозка сменила смысл:** «месяц закрыт, начисление получено», а не «не
  пересчитывать». Она убирает месяц из ежедневного дотягивания, разморозка
  возвращает. Текст в UI поправлен.

**Чтобы история пересчиталась, нужен полный синк** («перетянуть») — иначе
`factGross` за 2025 и начало 2026 в истории просто нет. Месяцы, у которых факт
уже сохранён, пересчитаются сразу: цену делит сам резолвер.
