# Задачи: перевести расчёт денег на модель из FOUNDATION

Модель и обоснования — [FOUNDATION.md](FOUNDATION.md). Здесь только порядок работ.
Один этап = одна законченная порция = один коммит. После каждого этапа
приложение собирается и работает.

Порядок не случайный: 1–3 не трогают ни сеть, ни UI; 4–6 добавляют сеть;
7 меняет экран; 8 независим и может идти когда угодно.

---

## 1. `EarningsContext` вместо четырёх `Double`

Сейчас `pricePerSession`, `pricePerDiagnostics`, `pricePerIntensiveChild`,
`monthlyTaxAmount` руками протащены через `computeMonthStats`,
`computeProfileYearStats`, `computeDaySummaryStats`, `computeProfileTotals`
и десяток composable (`CalendarScreen`, `CalendarDialogs`, `DayDetailsDialog`,
`ProfileContent`, `ProfileYearStatsSection`). Пятый параметр — снова десяток
файлов.

Ввести один объект-носитель, переписать сигнатуры и вызовы.

**Цифры не меняются.** Существующие тесты (`CalendarStatsCalculatorTest`,
`ProfileYearStatsTest`, `DaySummaryStatsTest`, `ProfitDisplaySettingsTest`)
проходят после механической правки конструкторов — это и есть проверка,
что рефакторинг чистый.

## 3. Расчёт берёт цену из истории

Провести приоритет из FOUNDATION 3.2 через калькуляторы:

```
MANUAL → его цена
есть факт → factGross ÷ sessions
факта нет → цена профиля
текущий/будущий месяц → цена профиля
```

Осторожно: в `computeMonthStats` цена используется дважды — в `grossEarned`
и в `statsByStudent`. Обе должны брать одну и ту же цену месяца, иначе
статистика по ученикам разъедется с суммой.

Здесь же:

- `availableStatsYears` (`ProfileYearStats.kt:66`) добавляет годы из истории,
  а не только из `dayData` — иначе месяцы без локальных записей не покажутся;
- `computeDaySummaryStats` за прошедший день берёт факт этого дня из API,
  и только при его отсутствии — цену месяца (FOUNDATION 3.4).

Ловушка: **ручные интенсивы складываются с фактом, а не заменяются им** —
в YClients их нет (GAPS п.7).

## 4. API-слой зарплат

`data/network/SalaryModels.kt` + три метода в `YClientsApi`:

- `salary/period/staff/daily/{s}/` — по дням;
- `salary/payroll/staff/{s}/calculation/` — список начислений;
- `salary/payroll/staff/{s}/calculation/{id}` — детализация.

Обработать явно: **422** — период в будущем или больше года, обрезать
и повторить; **403** — нет прав, тихий фолбэк; **401** — общий logout,
не дублировать.

Разбор не должен падать на незнакомом `item_type_slug` (бонусы, штрафы,
гарантированный минимум).

## 5. Заполнение истории и заморозка

- Первый логин — тянем историю, заполняем месяцы, `origin = AUTO`.
- Синк — текущий месяц каждый раз, прошлый один раз до заморозки.
- Заморозка: не текущий + факт есть + ≥ 7 дней → сверка.
- Совпало — `frozen`, молча. Не совпало — `frozen` по цене приложения,
  `resolved = false`.
- Кнопка «перетянуть историю»: `factGross` обновляется, ручное не трогается.

Не трогать live-опрос и push.

Тесты: месяц из факта, месяц без факта, месяц наполовину в будущем,
факт нулевой (не путать с «факта нет»), расхождение → `resolved = false`.

## 6. Профиль: АВТО/РУЧНОЕ и правильный источник цен

- Признак `origin` у каждой цены (FOUNDATION 6.1). АВТО обновляется при синке,
  РУЧНОЕ — никогда.
- Цены берём из детализации начисления (`salary_sum` позиции), а не из
  `ServiceData.cost`. Диагностика — 2250, а не цена клиента 4500.
- Добавить `first_cost` и `cost_per_unit` в `ServiceData`
  (`YClientsModels.kt:86-93`).
- Старую эвристику в `YClientsCalendarSync.kt:233-246` заменить, **не удалять
  раньше**, чем заработает новый источник: при 403 и офлайне она пока
  единственное, что заполняет поля.

## 7. UI статистики

В `ProfileYearStatsSection.kt` уже есть клик по месяцу (542–554),
`selectedMonthIndex` (345) и сводка (585–593). Достроить:

- дисклеймер на всех месяцах с `origin = AUTO`;
- отметку расхождения на месяцах с `resolved = false` — на графике,
  в сводке и в заголовке секции;
- раскрытие месяца: цена, откуда она, диагностики, интенсивы, налог, «закрыт»;
- правку цены за занятие → `origin = MANUAL`, `resolved = true`;
- разбор расхождения (диалог, FOUNDATION 4) и разморозку.

Всё подчиняется `ProfitDisplaySettings`; тумблер показа расхождений — туда же.
Секция остаётся презентацией: правка идёт колбэком наверх.

## 8. Независимые работы

Можно делать в любой момент, ни от чего не зависят.

- **Sidecar метаданных** (FOUNDATION 8.3): `SessionSlotKey → record_id,
  service_id, activity_id, first_cost`. Пишем при синке, пока не читаем.
  Чем раньше — тем больше истории.
- **Бэкап**: ключ `salary_ledger` в `CalendarDataStore.exportAllData()`.
  Отсутствие ключа при импорте = «не трогать историю», а не «очистить».

## Чего в этой задаче нет

- **Интенсивы 2025** — не считаем, решено.
- **Разбивка ЗП по каждой записи** через `record_id` — отдельная задача.
- **Налог и выплаты на карту** — YClients про них не знает, остаются ручными.
- **Push, live-опрос, уведомления, архив** — не трогать.
