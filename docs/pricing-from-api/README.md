## Главное

1. **Ставки «за занятие» до июня 2026 не существовало.** Схема была процентная:
   `percent 50` от базовой цены услуги. «1250», «1400», «1500» — это 50 % от
   прайса 2500 / 2800 / 3000. Фикс `1400` появился только с 01.06.2026,
   вместе с личной схемой ЗП.
2. **Смена прайса размазана по клиентам, а не по датам.** Старая и новая цена
   сосуществуют ~2,5 месяца (абонементы по старому прайсу). Поэтому правило
   «ставка X с даты Y» историю не восстанавливает — нужен факт из API.
3. **Текущая автоподстановка цены неверна вдвойне.** Она берёт `ServiceData.cost` —
   это оплата деньгами, у трети записей она `0` (абонемент), а у остальных это
   цена клиента, а не ЗП. Нужное поле — `first_cost`, его в модели нет.
4. **API отдаёт факт за всю историю и сходится сам с собой.** Посуточный расчёт
   и детализация начислений совпали до рубля во всех 18 закрытых месяцах.
5. **Будущее API не считает** (HTTP 422), поэтому прогноз по будущим записям
   остаётся на стороне приложения.

Диагностика: 3 штуки за всё время, по 2250. Интенсив: в 2025 начислялся **ноль**,
с июня 2026 — 1400 ₽ за пришедшего ребёнка.

Итого за 19 месяцев: **1708 занятий, 2 369 900 ₽**; за вычетом налога
6500 ₽/мес — 2 246 400 ₽.

## Куда двигать

Кэш факта `дата → сумма` из `salary/period/staff/daily/` — обязательная часть,
а не опция: одной ставкой прошлое не пересчитывается. Прогноз на будущее —
по ставке из последнего закрытого начисления. Подробно — раздел 7
в [HISTORY-2025-2026.md](HISTORY-2025-2026.md).

## Что нужно решить

- Ставка 1500 с августа 2026 — это `fix 1500` или снова процент? В API она
  появится только после первого отработанного дня августа.
- Интенсивы 2025 (в YClients по ним ноль) — считать по числу записанных?
- За 2025 год показывать факт (1250) или пересчёт по текущей ставке?

## Что в PLAN.md устарело

PLAN.md писался до разбора всей истории и утверждает, что ставки в API лежат
как `fix`, а история «просто отдаётся по 1250». На деле `fix` появился только
в июне 2026, до этого был процент, и переходы между прайсами перекрываются.
Из-за этого «Вариант 1» (подставить ставку в профиль) там оценён как
полноценный первый этап — он им быть не может, только как фолбэк.
Разбор эндпоинтов, ограничения и этапы 1, 3–6 остаются в силе.
