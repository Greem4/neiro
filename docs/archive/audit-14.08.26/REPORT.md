### B1 — что на самом деле оказалось в профиле

Аудит насчитал пять разошедшихся правил, разбирая исходники глазами. Сверка по
mapping-файлу R8 от релиза `0.1.6` (его `app/src` совпадает с этой веткой —
диффа нет) показала **17 не матчащихся правил из 33**:

| Причина | Правила |
|---|---|
| Сигнатура изменилась | `CalendarScreen`, `CalendarScreenContent` — переписаны точно по mapping |
| Метод заинлайнен, класс жив | `CalendarDataStore.peekSnapshot`, `computeMonthStats`, `rememberCalendarMonthStats` |
| Класс слит или удалён R8 целиком | `CalendarGridKt`, `DayCardKt`, `CalendarHeaderKt`, `StatComponentsKt`, `SessionParser`, `CalendarDataStoreProvider` — 12 правил |

Правила пишутся в исходных именах, а переводит их в имена собранного APK сам
AGP по mapping — поэтому сверять надо по нему, а не по dex, где имена уже
переименованы. Правила, чью сигнатуру подтвердить не удалось, удалены: молча не
матчащееся правило хуже отсутствующего, потому что создаёт видимость покрытия.
После правки **все 18 оставшихся правил совпадают** с релизным APK.

Как сверить в следующий раз, без Gradle и без устройства:

```bash
gh release download vX.Y.Z --pattern 'mapping*' --pattern '*.apk'
gunzip -k mapping-X.Y.Z.txt.gz
# 1) классы: строка вида `ru.greemlab.neiro.ui.components.CalendarGridKt -> ab:`
#    в НАЧАЛЕ строки. Нет её — класса в APK нет, правило мёртвое.
grep -c '^ru\.greemlab\.neiro\.ui\.components\.CalendarGridKt ->' mapping-X.Y.Z.txt
# 2) методы: внутри блока класса, строки с отступом вида
#    `    void CalendarScreen(<типы>) -> a` — имя метода без точек.
#    Инлайн-кадры (`… ru.greemlab…Kt.method(…):12:14 -> b`) не считаются:
#    у них имя квалифицированное, и своего класса у метода уже нет.
```

Дальше типы перевести в JVM-дескрипторы (`void` → `V`, `int` → `I`,
`java.time.YearMonth` → `Ljava/time/YearMonth;`, массив → `[` впереди) и сравнить
с правилом. Строку `HSPL` при сравнении отбросить — это флаги, не часть
сигнатуры.

Отсюда и второй коммит: для этого приложения написанный руками профиль живёт до
первой перестройки главного экрана — R8 сливает и инлайнит классы, и правила
перестают матчиться без единого предупреждения. Модуль `:baselineprofile`
(`com.android.test` + плагин `androidx.baselineprofile`) снимает профиль
настоящим холодным стартом.

## Где отступил от плана и почему

Четыре места. Все — потому что план расходился с кодом, а не ради удобства.

**1. `S1` — тест сделан на чистой функции, а не на инкрементальном синке.**
План требовал тест «инкрементальный синк вернул пустой месяц → `dayData` не
изменилась». Собрать `YClientsCalendarSync` в JVM-тесте нечем: `YClientsRepository`
и `SyncPreferences` — конкретные классы, берущие `Context`, а в
`testImplementation` только JUnit — ни Robolectric, ни mockk, ни
`coroutines-test`. Тянуть их ради одного теста значит трогать сборку, которая
работает. Вместо этого проверка вынесена в `shouldApplyCurrentMonthMerge` в
companion и покрыта тремя тестами, включая тот, что ловит настоящую ошибку:
границы берутся у **месяца**, а не у всего live-диапазона, иначе ученики
следующего месяца прикрывали бы пустой текущий. Сквозной тест пути остаётся
кандидатом на следующий заход — вместе с решением про тестовые зависимости.

**2. `K6` — сверяется владелец только активного устройства.**
План предлагал `existing.account_id != account_id` по `get_device`. Но выход из
аккаунта не удаляет строку, а ставит `revoked_at` — проверка «в лоб» намертво
заблокировала бы штатную смену аккаунта на том же телефоне (её же проверяет
пункт 4.3). Заведён `device_owner_account_id`, который видит только строки с
`revoked_at IS NULL`. Отдельным тестом закреплено, что после `logout` телефон
свободен для другого сотрудника.

**3. `K4` — добавлен сброс счётчика при успехе.**
План описывал только `note_upstream_auth_failure`. Но счётчик по смыслу считает
`401` **подряд** (так он и работает в прокси), а поллер его нигде не обнулял бы —
разовые сбои YClients копились бы неделями до порога. Добавлен
`clear_auth_failures` на удачную выборку, как в прокси.

**4. `D2` — `SessionMetaStore.clear()` вместо `deleteSharedPreferences`.**
Удалить файл мало, пока жив синглтон со своим объектом `prefs`: при первой же
записи он вернул бы старые значения обратно. Хранилище чистит себя само, и имя
файла остаётся в одном месте.

Отдельно: `U2` сделан по **варианту Б** (вывести), решение пользователя от
14.08.2026. При этом «налог за год» и «чистыми за год» арифметически не сходятся
и сойтись не могут — месяц без дохода даёт `net = 0`, а налог за него всё равно
начислен. Свели то, что сводится: источник ставки. Инвариант «год = сумма
налогов месяцев из разбора» закреплён тестом, расхождение с `monthlyNet`
описано в KDoc, чтобы следующий читатель не счёл его багом.
