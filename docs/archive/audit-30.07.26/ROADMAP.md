# Дорожная карта фиксов по аудиту 30.07.2026

Четыре волны по риску. Внутри волны порядок имеет значение: пункты идут так,
чтобы каждый следующий ложился на уже исправленное. Один пункт = один коммит,
сообщение — одной строкой на русском (правило [`CLAUDE.md`](../../../CLAUDE.md)).

**Порядок волн и объём — решение пользователя.** Ниже — предложение, а не план к
исполнению.

Ссылки на разбор каждого пункта — в [FINDINGS.md](FINDINGS.md).

### Старый `server/` не трогаем — решение пользователя от 30.07.2026

`server/` доживает как есть и гасится, когда все устройства перейдут на новый
сервис (`neiro-push-events`). Код в нём не правим — вкладываться в сервис,
который выключается, смысла нет.

Поэтому из волны 3 выпали `K2` (WAL и одно соединение), `K3` (детектор
изменений), `K4` (кеш google-токена), а `K5` из волны 2 и `K6`/`K7` из волны 4
закрываются самим гашением. Находки в [FINDINGS.md](FINDINGS.md) остаются как
описание состояния на дату аудита — они верны, просто чинить их не будем.

`K7` касался обоих сервисов; для `neiro-push-events` он остаётся в силе (см.
волну 4), для `server/` — снят.

## Вне дорожной карты

- [B4](FINDINGS.md#b4-низко--версия-приложения-в-документации-и-в-сборке-разная) —
  расхождение версии в `progress.md` (0.7.0.0) и `build.gradle.kts` (0.6.10.1).
  Нужно решение пользователя, что считать верным; агент журнал прошлого этапа не
  переписывает.
- **Ротация `NEIRO_PUSH_API_KEY` и YClients partner token** — тянется с аудита
  23.07.26, ручное действие на серверах. Ключи из git-истории по-прежнему
  скомпрометированы. С переходом на `neiro-push` (этапы 6–8) `partner_token`
  ушёл с телефона в `.env` на Pi, и менять его теперь можно без пересборки APK —
  сама ротация назначена последним шагом запуска
  ([ROLLOUT.md § Шаг 6](../../neiro-push/ROLLOUT.md#шаг-6--уборка)).
- **Переписывание git-истории** (`git filter-repo`) — решение пользователя.
- **Firebase BOM 33 → 34** — ломающее изменение, отдельным заходом.
- **Этап 10 push-сервиса** (гашение `server/`) — эксплуатация. Решено
  30.07.2026: сервис доживает без правок и выключается, когда все устройства
  перейдут на `neiro-push-events`. Пункты `K2`–`K4`, `K6` сняты, `K5` остаётся
  риском до выключения.

## Проверки после волн

Гоняет пользователь — агент Gradle не запускает.

**После волны 1**

- [ ] `./gradlew testDebugUnitTest` зелёный;
- [ ] оба сервиса поднялись после правки ключей (`docker compose logs`);
- [ ] `/dashboard` не пускает по клиентскому `API_KEY` и пускает по `ADMIN_API_KEY`;
- [ ] «Сменить аккаунт» → вход другим сотрудником → в дашборде у нового
      устройства курсор не унаследован от старого, уведомления приходят.

**После волны 2**

- [ ] изменение записи в YClients → уведомление приходит и статус в календаре
      меняется (push при закрытом приложении);
- [ ] отключить разрешение на уведомления → напоминание и утренняя сводка всё
      равно появляются в ленте внутри приложения;
- [ ] выключить сеть на телефоне на час → после включения keepalive
      восстанавливается, в `adb shell dumpsys jobscheduler` нет разрастания
      очереди `push_keepalive`.

**После волны 3**

- [ ] `neiro-push-events`: `/v1/admin/poll-log` — циклы идут, `events_created`
      совпадает с фактическими изменениями;
- [ ] дашборд открыт полчаса — `duration_ms` циклов не растёт;
- [ ] холодный старт приложения не даёт ANR/фриза на первом кадре;
- [ ] синхронизация месяца с интенсивом дважды подряд: во второй раз тост
      показывает 0 новых записей.

**После волны 4**

- [ ] `./gradlew testDebugUnitTest` и `pytest` в `neiro-push-events` зелёные
      (тесты `server/` не трогаем — сервис гасится);
- [ ] release-сборка с новыми правилами proguard запускается, push приходит
      (сужение `-keep` проверяется только на release).
