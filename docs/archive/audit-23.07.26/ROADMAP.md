# Дорожная карта исправлений — аудит 23.07.26

План работ по находкам из [FINDINGS.md](FINDINGS.md). Волны упорядочены по риску: сначала утечка секретов и молчаливые отказы фона, затем целостность данных, затем UI и статистика, в конце гигиена репозитория.

## Правила работы

- **Не запускать Gradle** — сборку и тесты гоняет пользователь; агент проверяет `ReadLints`.
- Коммиты: одна строка на русском, ≤72 символа, прошедшее время, без префиксов. Заготовки — в конце каждого пункта.
- Один пункт = один коммит.
- **Не трогать** ничего из [`docs/audit-17.07.26/OUT_OF_SCOPE.md`](../audit-17.07.26/OUT_OF_SCOPE.md).
- Фиксы прошлого аудита не откатывать; правки поверх них — только описанные ниже.

## Волна 1 — безопасность и критичные фоны (делать первой)

### 1.1 B1 — убрать AAB из git и ротировать ключи

1. `git rm --cached app/release/app-release.aab`; в `.gitignore` — `app/release/`, `*.aab`, `*.apk`.
2. **Ротация `NEIRO_PUSH_API_KEY` на push-сервере** (ключ в истории git — считать скомпрометированным). Обновить `local.properties` на машине сборки.
3. По желанию — `git filter-repo` для чистки истории (согласовать: перепишет хэши всех веток).

Коммит: `Убрал release-артефакт с секретами из репозитория`

### 1.2 S1 — guard'ы в finally воркеров + проброс cancellation

`PushKeepAliveWorker`, `LiveApiRefreshWorker`: в `finally` планировать следующее звено только при `!isStopped`; `runCatching` вокруг suspend-вызовов заменить на try/catch с пробросом `CancellationException` (или `ensureActive()` после). Для live дополнительно — `!PushConfig.isActive`.

Коммит: `Перестал воскрешать цепочки воркеров после logout`

### 1.3 S2 — развести retry и self-reschedule у LiveApiRefreshWorker

При Failure — `Result.retry()` **без** `scheduleNext`; `scheduleNext` только при успехе. Симметрично S6 (keepalive: `Result.retry()` при ошибке без scheduleNext) — можно одним коммитом с 1.2, если правка общая.

Коммит: `Убрал раздувание очереди live-опроса при ошибках`

### 1.4 N1 — починить потерю напоминаний

`REMINDER_WINDOW_HALF` → 10; catch-up в `runReminderCheck` (`0 ≤ minutesUntilStart ≤ reminderMinutesBefore` и не notified → показать); в `rescheduleReminders` при `delayMs <= 0`, но сессия в будущем — enqueue с нулевой задержкой. Обновить `UpcomingSessionsCollectorTest`.

Коммит: `Исправил потерю напоминаний между тиками воркера`

## Проверки после волн

- **Волна 1:** `git ls-files '*.aab' '*.apk'` пуст; старый push-ключ отклоняется сервером; logout → WorkManager Inspector: `push_keepalive`/`yclients_live_api_refresh` не переустанавливаются; включить напоминание за 15 мин → sync за минуту до срока → напоминание всё равно приходит.
- **Волна 2:** перенести запись в YClients на другой день → старый день чистится ближайшим инкрементом; открытое приложение с push обновляется не реже раза в 5 мин; logout → нет воркера `push_fcm_sync`.
- **Волна 3:** смена времени сводки применяется мгновенно (Inspector: один enqueued digest); отключить разрешение на уведомления → изменения из YClients видны в ленте внутри приложения.
- **Волна 4:** 401 во время повторного логина → новая сессия живёт; смена цены во время фонового sync не теряет остальные поля профиля; Layout Inspector — один парс снапшота на эмиссию.
- **Волна 5:** архивный день с mismatch → кнопка предлагает перезапись; интенсив без времени с детьми переживает сохранение/перечитывание; убить процесс с открытым днём → день восстановлен.
- **Волна 6:** двойной тап по «Войти» → один запрос; «Сменить аккаунт» → сразу форма входа; тумблер уведомлений синхронен на обоих экранах.
- **Волна 7:** `connectedDebugAndroidTest` зелёный; CI зелёный на PR.
