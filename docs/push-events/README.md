# Сервис событий `neiro-push-events`

Новый push-сервис, который сам вычисляет, **что именно** изменилось в занятии, и
присылает на телефон готовое событие — вместо нынешнего «сходи и перечитай
месяц». Ставится рядом с работающим `neiro-push`, не трогая его.

Код: [neiro-push-events/](../../neiro-push-events/). Ветка: `фикс-уведомлений`.

## Документы

**[plan.md](plan.md)** — главный план. Архитектура, контракт FCM-payload и API,
правила диффа, десять этапов с приёмкой, чек-листы, грабли. Источник правды по
тому, **как должно быть**.

**[progress.md](progress.md)** — журнал работ. Что сделано по этапам и какими
коммитами, что проверено вживую, семь подводных камней, найденных по ходу, и
таблица решений пользователя с датами. Источник правды по тому, **как есть**.

**[stage5-review.md](stage5-review.md)** — разбор Этапа 5. Поллер написан и
закоммичен, но сверка с планом нашла два блокера (ложные `NEW_BOOKING` из-за
рассинхрона сидирования; риск потерять событие из-за порядка записи) плюс
невыполненный раздел про логи. Внутри — сценарии поломки, готовые решения и
порядок из шести коммитов. **Это следующая работа.**

**[app.md](app.md)** — детализация Этапа 8: правки Android-приложения. Разбор по
файлам, четыре жёстких требования к payload, применение события к календарю,
догон, риски, приёмка.

## Текущее состояние

Этапы 0–5 закоммичены, сервис поднят на Pi и отвечает на `/v2/health`. Старый
`neiro-push` (сборка 0.6.9.0) работает как работал и не тронут.

**Этап 5 не закрыт** — см. [stage5-review.md](stage5-review.md).
