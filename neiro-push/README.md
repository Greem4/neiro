# neiro-push

FastAPI-сервис на Raspberry Pi: держит ключи YClients у себя, пускает
приложение по отзываемому `device_token` и проксирует запросы в YClients.
Плюс всё, что умеет второе поколение: опрашивает YClients, превращает
изменения записей в события (новая запись, подтверждение, приход, отмена,
перенос, удаление) и рассылает их устройствам через FCM data-push.

Третье поколение сервиса под этим именем. Второе (`neiro-push-events`,
порт 8011, путь `/v2`) продолжает работать рядом и обслуживает установленное
приложение до конца перехода — [DEPLOY.md § Три поколения](../docs/neiro-push/DEPLOY.md#три-поколения-сервиса).

Главное отличие от предшественника: `partner_token` и `user_token` в APK и на
телефоне больше не живут. Телефон знает только свой `device_token`, а он
привязан к одному аккаунту и отзывается кнопкой.

## Состояние

Серверная часть готова целиком — **Этапы 1–5**: каркас, вход с выпуском
`device_token`, прокси YClients, лимиты и отзыв устройств, деплой на Pi.
Дальше — приложение (Этапы 6–8): сетевой слой переводится на прокси, и ключи
YClients уходят из APK. План — [TASKS.md](../docs/neiro-push/TASKS.md).

## Доступы

Всё, чем открывается сервер, лежит в одном месте — `neiro-push/.env` (файл в
`.gitignore`, шаблон рядом: [`.env.example`](.env.example)). Там же в шапке
адреса, ssh-хосты и команды скриптов. Главное:

- `ADMIN_API_KEY` — **пароль от дашборда** `https://push.neiro.greemlab.ru/`,
  вставляется целиком в поле «ключ»; он же открывает `/health` и `/v1/admin/*`
  заголовком `Authorization: Bearer …`. Кука после входа живёт 30 дней.
- `API_KEY` — ключ приложения, только для `POST /v1/auth/login`. Его копия
  лежит в `local.properties` как `NEIRO_PUSH_API_KEY`.

Источник правды — `~/neiro-push/.env` на самом Pi; локальный файл ещё и
конфигурация для `dev.sh`. В `local.properties` держим только то, что читает
Gradle: адрес сервиса и ключ приложения.

## Старт

Команда запускается **из корня репозитория** — никуда переходить не нужно.

```bash
./neiro-push/scripts/dev.sh            # локально
./neiro-push/scripts/dev.sh --reset    # локально, с чистыми тестовыми данными
```

Дашборд — `http://127.0.0.1:8012/dashboard`. Код и шаблоны подхватываются на
лету, пересобирать контейнер не нужно.

Тесты:

```bash
cd neiro-push && PYTHONPATH=. python -m pytest tests -q
```

## Эндпоинты

Спецификация — [API.md](../docs/neiro-push/API.md). Поднято всё, что там
описано:

| Метод | Путь | Ключ | Что делает |
|-------|------|------|------------|
| POST | `/v1/auth/login` | `API_KEY` | Вход по логину и паролю YClients; выдаёт `device_token` |
| POST | `/v1/auth/logout` | `device_token` | Отзыв токена устройства; аккаунт остаётся |
| GET | `/v1/session` | `device_token` | Состояние без похода в YClients, включая `reauth_required` |
| POST | `/v1/devices/fcm` | `device_token` | Обновление токена FCM |
| GET | `/v1/yclients/records` | `device_token` | Записи филиала за период; `staff_id` подставляет сервер |
| GET | `/v1/yclients/clients` | `device_token` | Клиенты филиала |
| GET | `/v1/yclients/staff` | `device_token` | Карточки сотрудников (`book_staff`) |
| GET | `/v1/yclients/salary/daily` | `device_token` | Начисления по дням |
| GET | `/v1/yclients/salary/calculations` | `device_token` | Расчёты за период |
| GET | `/v1/yclients/salary/calculations/{id}` | `device_token` | Детализация расчёта |
| POST | `/v1/admin/devices/{id}/revoke` | `ADMIN_API_KEY` | Отзыв `device_token` устройства; строка остаётся в списке |
| DELETE | `/v1/admin/devices/{id}` | `ADMIN_API_KEY` | Удаление устройства совсем; телефону придётся войти заново |
| POST | `/v1/admin/accounts/{id}/reset` | `ADMIN_API_KEY` | Потребовать повторный вход паролем |
| GET | `/health` | `ADMIN_API_KEY` | Статус: аптайм, число аккаунтов и устройств, события за сутки |
| GET | `/v1/admin/events` | `ADMIN_API_KEY` | Последние события с числом доставок |
| GET | `/v1/admin/poll-log` | `ADMIN_API_KEY` | Журнал циклов опроса |
| GET | `/v1/admin/dashboard.txt` | `ADMIN_API_KEY` | Дашборд текстом |
| GET | `/dashboard` | cookie | Дашборд, вход по `ADMIN_API_KEY` |

Маршрутов старого API (`/v1/devices/register` с токенами YClients в теле,
`/v1/devices/{id}/events`) здесь нет и не будет — они остались во втором
поколении, [API.md § Чего здесь нет](../docs/neiro-push/API.md#чего-здесь-нет).

Лимиты: вход — 5 попыток за 15 минут на `device_id` и на IP, прокси — 60
запросов в минуту на устройство. Превышение даёт `429` с `Retry-After`.
Удачный вход счётчик обнуляет.

## Эксплуатация

```bash
./neiro-push/scripts/deploy.sh                    # выкатить на Pi
./neiro-push/scripts/logs.sh --errors             # ошибки за сутки
./neiro-push/scripts/backup.sh                    # база и .env на Mac
./neiro-push/scripts/restore.sh <файл>            # откат базы
./neiro-push/scripts/revoke-device.sh <device_id> # отобрать доступ у телефона
```

На странице устройства в дашборде — три кнопки:

| Кнопка | Что делает | Строка в списке |
|---|---|---|
| Отозвать устройство | `device_token` перестаёт работать | Остаётся, помечена отозванной |
| Сбросить аккаунт | Аккаунту нужен повторный вход паролем; устройства и пуши живы | Остаётся |
| Удалить устройство | Строка уходит из базы, доступ пропадает | Исчезает |

Для телефона отзыв и удаление неотличимы: `require_device` не находит токен,
отвечает `401`, приложение уходит в локальный режим и просит войти заново.
Разница в том, что после отзыва устройство продолжает висеть в списке, а после
удаления — нет; вернётся оно туда при следующем входе.

Удаление необратимо. История доставок этого устройства остаётся привязанной к
событиям (по ней считается, скольким телефонам ушёл пуш) и отживает свои
90 дней сама.

Формы на этой странице отправляют `dashboard/devices/{id}/<действие>` —
`device_id` в `action` обязателен: адрес страницы идёт без завершающего слеша,
и относительный `action="revoke"` браузер разрешал в `dashboard/devices/revoke`,
получая `405` ([ROLLOUT.md § Кнопки на странице устройства](../docs/neiro-push/ROLLOUT.md#кнопки-на-странице-устройства-11082026)).

## Настройки

`.env` рядом с `docker-compose.yml`, образец — [.env.example](.env.example).
Отличия от второго поколения:

| Переменная | Зачем |
|---|---|
| `YCLIENTS_PARTNER_TOKEN` | Единственное место, где партнёрский токен теперь живёт. Пустой — сервис не сможет ни залогинить пользователя, ни опросить YClients |
| `YCLIENTS_COMPANY_ID` | Филиал по умолчанию при входе; телефон его больше не знает |
| `DATABASE_PATH` | `/data/neiro_push.db` |

## Схема БД

Против прежней схемы: колонки `partner_token_enc` нет вовсе, у аккаунта
появились `user_login`, `user_name`, `avatar_url`, `reauth_required`,
`auth_failures`, `last_auth_at`, у устройства — `token_hash` (SHA-256 от
`device_token`, сам токен не хранится) и `revoked_at`.

База живёт между выкатками, поэтому новые колонки добавляются не только в
`SCHEMA`, но и в `Database._add_missing_columns`: `CREATE TABLE IF NOT EXISTS`
про них не знает — таблица уже есть, и он молча ничего не делает.

Разбор — [ARCHITECTURE.md § Схема БД](../docs/neiro-push/ARCHITECTURE.md#схема-бд).

## Что хранится и сколько

В `poll_runs` попадают только значимые циклы — с событиями, пушами или
ошибкой. Пустой скан («сходил, изменений нет») не пишется: при опросе раз в
10 секунд таких набегало больше 8 тысяч в сутки. «Сервис жив и когда ходил
последний раз» живёт в памяти поллера (`PollService.last_run_at`), поэтому
сразу после рестарта шапка дашборда показывает прочерк — до первого цикла,
то есть не дольше `POLL_INTERVAL_SECONDS`.

События, доставки и циклы хранятся **90 дней** скользящим окном; чистка
запускается не чаще раза в час. Подробнее и с обоснованием —
[ARCHITECTURE.md § Что попадает в журнал циклов](../docs/neiro-push/ARCHITECTURE.md#что-попадает-в-журнал-циклов-а-что-нет).
