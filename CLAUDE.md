# Правила для агента

## Git-коммиты — только на русском, кратко

- Одна строка, до 72 символов, без тела коммита и переносов.
- Одна главная мысль — не перечислять файлы, классы, параметры, детали реализации.
- Глагол в прошедшем времени: «Добавил», «Исправил», «Обновил», «Убрал», «Перенес».
- Без префиксов `feat:`, `fix:`, `chore:`.
- Имена в коде можно латиницей, описание — только русский.

Примеры:
- Добавил API ежемесячных выплат Pay
- Исправил жесты drawer с левого края
- Обновил PayMonthlyChart

Нельзя:
- «Добавлены новые модели и маршруты… Обновлены стили…»
- `Refactor CalendarHeader for improved usability`
- любое сообщение длиннее одной короткой фразы

## Без Gradle-сборки

Никогда не запускать `./gradlew` или любые Gradle-команды (`assembleDebug`, `build`, `test` и т.п.).
Сборку и тестирование пользователь делает сам — задача агента только писать код.

## Расходится с реальностью — остановись и спроси

Если план, документация, комментарий в коде или задача расходятся с тем, что
на самом деле в коде — **остановиться и спросить пользователя**, а не
домысливать и не подгонять одно под другое молча.

Это же касается любых неозвученных допущений: не знаешь, какой из двух путей
имел в виду пользователь — спроси, а не выбирай молча тот, что удобнее.

Почему: молча выбранное допущение выглядит как выполненная работа, и ошибка
всплывает уже в бою. Вопрос стоит минуту, разбор последствий — дни.

## Не ломать то, что работает

Правки не должны задевать код и сервисы, которые сейчас работают и не входят
в задачу. Если для решения задачи нужно тронуть работающее — сначала сказать
об этом и получить согласие.

Отдельно про рефакторинг: `try/finally` и подобные конструкции часто стоят там
намеренно. Прежде чем «упрощать» такое в ранние `return`, понять, зачем это
написано — особенно если рядом есть комментарий с объяснением.

## Крупную задачу — этапами, коммит на этап

Один этап = одна законченная порция = один коммит. Не сваливать несколько
логических изменений в один большой коммит: в таком коммите незамеченным
проезжает поломка, и его невозможно откатить по частям.

**Это правило работает только в автономном режиме** — когда задача идёт по
заранее написанному плану/шаблону/пунктам (md-файл с планом, автономный
луп, cron-агент) и рядом нет пользователя, который может остановить на
каждом шаге. При обычной работе напрямую с пользователем в диалоге —
**коммитить только когда пользователь явно попросил закоммитить**, не
коммитить автоматически после каждого этапа молча.
