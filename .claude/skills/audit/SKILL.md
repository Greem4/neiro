# Аудит проекта Neiro

## Первым делом

Прочитать [`docs/audit/METHODIKA.md`](../../../docs/audit/METHODIKA.md) целиком и
работать по ней. Там: границы аудита, метрики базы, процедура из семи шагов,
чек-листы по областям, критерии серьёзности, формат находки, состав пакета
документов, история прошлых аудитов и список незакрытого.

Затем — [`docs/audit-17.07.26/OUT_OF_SCOPE.md`](../../../docs/audit-17.07.26/OUT_OF_SCOPE.md)
и `REPORT.md` последнего пакета ([`docs/audit-23.07.26/REPORT.md`](../../../docs/audit-23.07.26/REPORT.md)).

## Границы

`app/` (Android, ~21 700 строк Kotlin) + `server/` (FastAPI, push-сервер) +
`neiro-push-events/` (сервис событий). Бэкенды аудита ещё не проходили.

## Что делает этот заход

Находит проблемы и **записывает документы** — код не правит:

1. Зафиксировать базу: ветку, версию, `git log` с даты прошлого аудита, метрики.
2. Сверить фиксы прошлого аудита по его `REPORT.md` — регрессии в приоритет.
3. Пройти области `B` `S` `N` `D` `U` `P` `K` `E` по чек-листам методики. Крупные
   файлы читать целиком; граф codebase-memory — для навигации и поиска вызовов.
4. Каждую находку верифицировать: найти код, делающий путь достижимым. Нет
   сценария отказа — нет находки.
5. Создать `docs/audit-DD.MM.YY/` с `README.md`, `ARCHITECTURE.md`,
   `FINDINGS.md`, `ROADMAP.md` (`REPORT.md` — позже, после фиксов).
6. Показать TL;DR по критичному и высокому и **остановиться**: что и в каком
   порядке чинить, решает пользователь.

## Жёсткие правила

- **Не запускать Gradle** — сборку и тесты гоняет пользователь.
- **Не править код** в этом заходе; фиксы — отдельный заход по `ROADMAP.md`,
  один пункт = один коммит.
- **Не коммитить** без явной просьбы пользователя.
- **Не считать находкой** то, что есть в `OUT_OF_SCOPE.md`.
- Код расходится с планом или документацией — **спросить**, не подгонять.
- Документы прошлых аудитов не переписывать.
